The keys

Colour says it before you read it.

Anything that needs you also gets a glyph, and only those blink.

Needs you

Amber and blinking, marked !. Waiting on an approval or an answer.

Failed

Red and blinking, marked ✕. The latest run failed.

Done

Green, marked ✓. Finished while you were away. Never blinks.

Working

Blue spinner. The agent or a subagent is running.

Subagents

The badge counts those working inside the thread.

Waiting on something

White spinner. Background work, like a PR's CI, is still running.

Usage limit

Dashed and dim, with a countdown to when it resumes.

Idle

Quiet. Leaves the deck after 8 hours by default.

Overview

Counts it all. Tap for the full threads page; hold to clear highlights.

Back

Returns to your previous profile. The chevron turns amber when something needs you.

More about the keysContext bar, +N, highlights, error keys
  • Context bar: the thin line along the bottom shows how full the context window is: grey, amber from 70%, red from 85%.
  • +N and +N more: threads that don't fit on this deck's Thread keys.
  • Highlights: done and failed clear when you open the thread, from the key or from T3 Code. Having it open while the run finishes doesn't count.
  • When T3 Code isn't reachable: the first Thread key says why (Install T3 Code, Open T3 Code, T3 CLI missing, Sign-in failed, Signed out or T3 error) and the rest go blank rather than show stale state.

Thread Actions

Hold a key. Steer the thread.

Hold a thread key for half a second, then let go. You get a page just for that thread.

Quick messages

Your own lines, like "continue", sent as if you'd typed them.

Compact and snooze

Trim the context, or send a thread away for a while.

Hold to confirm

Risky keys need a 0.8-second hold. A stray tap does nothing.

Usage tile

Pace your limits.

Pick any limit T3 Code reports. The white tick marks even pace.

Reading the tileBar, ring, colours, refresh
  • Bar: percent used, how far ahead or under pace you are (within 3 points is on pace), and time to reset.
  • Ring: one segment per day for weekly limits, per hour for the 5-hour one.
  • Colour is pace: green under, blue on pace, amber ahead, red when far ahead (15+ points on the ring) or at 90%.
  • Tap to refresh. Otherwise every 5 minutes, and only while a Usage key is on your deck.

Where tokens liveLocal storage, loopback only, scrubbed logs
  • Made by your local t3 CLI and stored in ~/Library/Application Support/io.github.hsalazr.deck-for-t3code/, readable only by you. In t3 auth session list they show as Stream Deck (Deck for T3 Code…).
  • Only ever sent to 127.0.0.1, localhost or ::1.
  • The t3 CLI only runs if it's a regular file you (or root) own and nobody else can write to.
  • Logs are scrubbed of anything that looks like a token. No analytics, no crash reports.
Updates and loadLive stream, 30-second check, light on T3 Code
  • A live stream from T3 Code pushes changes. The thread list is re-read when something changes (no more often than your "Refresh every" setting, 2 seconds by default) and every 30 seconds to be sure.
  • Usage limits: every 5 minutes, and only while a Usage key is on your deck.
  • Context size: only for threads on a key, when they first appear, when a run ends, and at most every 2 minutes while one works.
Revoking accessOne button, or two CLI commands
  • Press Sign out / revoke tokens in the plugin's settings. Sign in again resumes.
  • Or run t3 auth session list, then t3 auth session revoke <id>.
  • A revoke that can't happen right away is retried every time the plugin starts.
  • Do it before you uninstall: removing the plugin doesn't revoke its tokens.

Install

Two minutes, tops.

  1. Check the basics

    macOS 13+, the Stream Deck app 7.1+, and T3 Code installed and running.

  2. Install the plugin

    From the Stream Deck Marketplace (link coming soon), or double-click the .streamDeckPlugin from GitHub Releases.

  3. Drag keys onto your deck

    Add an Overview key, a few Thread keys and, if you like, a Usage key.

  4. That's it

    Nothing to pair. For Thread Actions, tick Enable thread actions in a key's settings.

Build it yourselfFree to fork. Needs Node 24. 
git clone https://github.com/hsalazr/deck-for-t3code.git

npm ci
npm run build
npx streamdeck link *.sdPlugin

FAQ

Good questions.

Windows or Linux?

Not yet. macOS 13 or later only, and T3 Code has to run on the same Mac.

Do I need T3 Code?

Yes. The plugin is a window onto it and does nothing without it. Get T3 Code (free, macOS).

Which Stream Decks work?

Any deck with keys shows Thread, Overview and Usage keys. Full pages are bundled for the XL, the 15-key Stream Deck (including MK.2), the Neo and the Mini; see the table above. Dials and touch strips aren't used.

What does it see, and what leaves my Mac?

It reads thread titles, project names, run status, background task names, context size and usage limits from T3 Code, to draw the keys, and keeps them in memory only. Nothing leaves your Mac.

Can it change my threads?

Only if you turn on Enable thread actions. Until then every token is read-only.

How do I remove access?

Press Sign out / revoke tokens in the plugin's settings before you uninstall. Other ways are under How it works.

A key says "Sign-in failed" or "T3 CLI missing"

The plugin couldn't get a token. Check that T3 Code is running, that ~/.t3/bin/t3 exists and isn't writable by others (chmod go-w), and that you haven't signed out (press Sign in again). If your T3 data lives elsewhere, set T3 home to its absolute path.

Is it affiliated with T3 Code?
