More about the keysColour, context bar, +N, highlights, errors
  • Colour and motion: needs you (waiting on an approval or answer) and failed (the latest run failed) blink; nothing else does. Done stays steady. A waiting subagent makes its thread's key flash, and the Back key's chevron turns amber when anything needs you. Working means the agent or a subagent is running.
  • Context bar: the thin line along the bottom shows how full the context window is: grey, amber from 70%, red from 85%.
  • +N and +N more: threads that don't fit on this deck's Thread keys.
  • Highlights: done and failed clear when you open the thread, from the key or from T3 Code. Having it open while the run finishes doesn't count.
  • When T3 Code isn't reachable: the first Thread key says why (Install T3 Code, Open T3 Code, T3 CLI missing, Sign-in failed, Signed out or T3 error) and the rest go blank rather than show stale state.

New · Two looks

Read it from across your desk.

Every key comes in two looks. Detailed packs in the title, project, context and status. Glance keeps only what you can read from across your desk: the title in large type, with colour and motion telling you the state. Pick it under Thread keys in the settings; Machine and Updates keys have their own Style.

Reading the Glance look
  • Colour and motion: amber blinks when a thread needs you, red blinks when it failed, solid green when it's done, a blue stroke runs round the border while it works, a white one while only background work (CI, a subagent) is left, and a dashed border when a usage limit paused it.
  • Title: 26 px, up to four lines; a long one ends in "…". No icons, numbers, project name or context bar.
  • Overview: how many threads are in the most urgent state, big (failed first, then needs you, done, working, waiting), then "/" and how many threads there are in all, smaller. What it counts sits on top.
  • Machine and Updates: a ring the size of the Usage ring with the number in the middle, or a disc with a check or a count. See them.

  • Other models: decks like the Stream Deck + have no bundled pages. Thread, Overview, Usage, Machine and Updates keys still work, Overview jumps to the most urgent thread, and a hold on a Thread key clears its highlight.
  • Holds: opening the page takes half a second. Risky keys (Compact, Settle, Stop and quick messages) fire after 0.8 s; a tap only shows "Hold to confirm", so a stray tap does nothing.

  • Opt-in: off until you tick Enable thread actions, which mints a separate token. More on tokens.

Usage key

Pace your limits.

Pick any limit T3 Code reports. The white tick marks even pace.

Reading the Usage key
  • Bar: percent used, how far ahead or under pace you are (within 3 points is on pace), and time to reset.
  • Ring: one segment per day for weekly limits, per hour for the 5-hour one.
  • Colour: green under pace, blue on pace, amber ahead, red when far ahead (15+ points on the ring) or at 90%.
  • Tap: refreshes now. Otherwise see Updates and load.

New · Machine and Updates keys

Know your Mac has room.

CPU, memory and disk for this Mac, with performance and efficiency cores apart, and a key that says when T3 Code or a provider CLI has an update waiting. Pick one big number you can read from across your desk, or the detailed look.

How the Machine key measures
  • CPU: how busy the cores were over the last 30 seconds, from the busy and idle time macOS counts for each core. Amber from 70%, red from 90%. Thirty seconds keeps a short compile burst from flashing red while still catching sustained load.
  • P and E cores: Apple silicon has fast performance (P) cores and slower efficiency (E) cores, and macOS sends background work to the E cores, so they often look busy while the P cores, where builds and agents run, are free. The big number and the colour follow the P cores; the bar or ring is split into a P part and an E part, each as long as its share of the cores. The plugin reads which core is which from the hardware, so it fits any M-series chip; Intel Macs show all cores as one.
  • Why not the load average: it's an average of how many threads are running or waiting for a CPU, over the last minutes, so it trails behind: after a burst of work it can still read 40 while the CPUs sit mostly idle. The detailed look still shows it, small, for reference.
  • Memory: coloured by macOS's own memory pressure, not by how full memory looks. Why pressure?
  • Disk: space you can still write on the disk holding the folder you pick (the startup disk by default), in decimal units like Finder. Amber from 90% used or under 25 GB free, red from 95% or under 10 GB. Purgeable space isn't counted as free.
  • When: every 5 seconds, only while a Machine key is on a deck. All from macOS, so it works with T3 Code closed. Tap for Activity Monitor; a disk key opens its folder in Finder.
How the Updates key checks
  • T3 Code: compared with the newest release on its own channel: stable, or nightly if you run a nightly build. T3 Code's server looks this up; the plugin never goes online.
  • Provider CLIs: Claude, Codex and the rest come from T3 Code's own update checks, so leave Check for provider updates on in T3 Code's settings.
  • When: every 30 minutes while the key is on a deck. Tap to open T3 Code when an update is waiting, or to check again.

Why memory pressure

A full Mac isn't a struggling Mac.

macOS puts spare memory to work as cache, so "memory used" sits near the top on a perfectly healthy Mac. The Machine key colours memory by pressure instead: how hard macOS has to work to find room.

  2. 2

Where tokens liveStorage, loopback, logs
  • Made by your local t3 CLI and stored in ~/Library/Application Support/io.github.hsalazr.deck-for-t3code/, readable only by you. In t3 auth session list they show as Stream Deck (Deck for T3 Code…).
  • Only ever sent to 127.0.0.1, localhost or ::1.
  • The t3 CLI only runs if it's a regular file you (or root) own and nobody else can write to.
  • Logs are scrubbed of anything that looks like a token. No analytics, no crash reports.
Updates and loadWhat is polled, and when
  • A live stream from T3 Code pushes changes. The thread list is re-read when something changes (no more often than your "Refresh every" setting, 2 seconds by default) and every 30 seconds to be sure.
  • Usage limits: every 5 minutes, and only while a Usage key is on your deck.
  • Context size: only for threads on a key, when they first appear, when a run ends, and at most every 2 minutes while one works.
Revoking accessOne button or two commands
  • Press Sign out / revoke tokens in the plugin's settings. Sign in again resumes.
  • Or run t3 auth session list, then t3 auth session revoke <id>.
  • A revoke that can't happen right away is retried every time the plugin starts.
  • Do it before you uninstall: removing the plugin doesn't revoke its tokens.

Install

Two minutes, tops.

  1. Check the basics

    macOS 13+, Stream Deck app 7.1+, T3 Code running on the same Mac.

  2. Install the plugin

    Marketplace listing: Coming soon. Until then, double-click the .streamDeckPlugin from GitHub Releases.

  3. Add keys to your deck

    An Overview key, a few Thread keys, optionally a Usage key.

  4. Unlock Thread Actions (optional)

    Tick Enable thread actions in a key's settings.

FAQ

Good questions.

Windows or Linux?

Not yet. macOS 13 or later only.

Do I need T3 Code?

Yes. The plugin is a window onto it and does nothing without it. Get T3 Code.

Which Stream Decks work?

Any deck with keys. Full pages are bundled for the XL, the 15-key Stream Deck, the Neo and the Mini; other models get the keys only (see the table under Thread Actions). Dials and touch strips aren't used.

What does it see, and can it change anything?

It reads thread titles, project names, run status, background task names, context size and usage limits from T3 Code, to draw the keys, and keeps them in memory only. Nothing leaves your Mac.

It can only change threads if you turn on Enable thread actions. Until then every token is read-only. To remove access, see Revoking access under How it works.

A key says "Sign-in failed" or "T3 CLI missing"

The plugin couldn't get a token. Check that T3 Code is running, that ~/.t3/bin/t3 (or bin/t3 in your T3 home) exists and isn't writable by others (chmod go-w), and that you haven't signed out (press Sign in again). If your T3 data lives elsewhere, set T3 home to its absolute path. If ~/.t3 has never been used and there is one custom build's folder next to it (say ~/.t3-custom), that folder is found on its own.

Is it affiliated with T3 Code?

No. It's an independent community project, and the key pictures here use made-up example data.
